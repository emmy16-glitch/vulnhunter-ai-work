## Real candidate observations

The corrected integrated run persisted **12 candidate observations**: one Androguard sensitive-permission observation and eleven YARA observations. The YARA rules identified WebView JavaScript bridge surfaces under CWE-749 and remote dynamic-code-loading surfaces under CWE-494 across extracted DEX content. These observations remain in `evidence_required` status. They are not promoted to verified findings without deterministic code-path validation and review.

The full run’s persisted YARA output also scanned the generated JADX tree and produced additional duplicated/sibling observations. This is why the full run contained sixteen observations, including two operational-failure observations. The acceptance harness reports the exact run-specific counts rather than merging separate receipts into a misleading “full analysis” claim.

## Bugs exposed and fixes applied

The first real V380 run exposed an incorrect kernel-boundary diagnosis. `RLIMIT_FSIZE` was set to the per-file limit even though it is an individual-file kernel limit, not an aggregate workspace quota. The worker now uses `maximum_generated_bytes` for the kernel guard and retains the stricter per-file and total-workspace checks in `enforce_workspace_bound()` after each tool returns. The same run also showed that exit code `-24` is **SIGXCPU**, not SIGXFSZ; the CPU guard is now separated from the wall-clock timeout and scaled for multi-threaded JVM tools.

The Androguard adapter originally called `AnalyzeAPK`, which constructs a whole-program cross-reference graph and raised `MemoryError` while processing V380’s twelve DEX files. The adapter now validates the APK manifest with `APK` and parses DEX files independently, avoiding the cross-reference graph while retaining deterministic package, SDK, permission, class-count, and API-inventory evidence. The patched adapter completed both directly and through the signed worker harness.

## Reproduction

Run the durable harness from the repository root with a reviewed, private worker policy and an external runtime directory:

```bash
python3 scripts/run_mobile_apk_acceptance.py \
  /home/ubuntu/upload/V380.apk \
  --runtime-root /tmp/vh-v380-analysis/acceptance-runtime \
  --policy /tmp/vh-v380-analysis/mobile_static_worker_androguard_fixed.json \
  --requested-by real-v380-acceptance
```

The harness validates the artifact with `MobileArtifactIngestor`, creates a signed job, executes `MobileStaticQueueService`, validates the terminal receipt and signed progress snapshot, and emits a capability classification. It never runs the APK and never bypasses the dynamic-analysis gate.
